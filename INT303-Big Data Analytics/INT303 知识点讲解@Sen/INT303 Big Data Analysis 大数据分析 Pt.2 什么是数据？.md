# 1. 什么是数据？
数据是由多个数据对象（或称为记录、点、案例、样本、实体或实例）及其属性组成的集合。
属性是描述数据对象的特征，例如名字、出生日期、身高、职业等。
属性(Attribute)也被称为变量(variable)、字段(field)、特征(characteristic)或特性(feature)。

对于每个数据对象，其属性都会有具体的值。
一个数据对象可以通过一系列属性-值对来描述，这些对指定了对象的每个属性的具体值。
对象(object)也被称为记录(record)，点(point)，实例(case)，例子(sample)，实体(entity)，事例(instance)。

## 1.1 关系型数据（Relational Data）
关系型数据这个术语来自于数据库领域，其中数据被存储在具有固定模式（即固定属性集）的关系型表中。
在数据库中，通常假设表是稠密的（dense），换句话说，表中的空值很少，大多数属性都有值。
这种形式的数据有很多，例如，人口普查数据就是以这种形式存储的。
也有许多数据不适合这种形式：
稀疏数据（Sparse data）：包含许多缺失值。
不易定义固定模式（Not easy to define a fixed schema）：数据的结构不固定或变化很大，难以用传统关系型数据库来表示。

## 1.2 属性（Attributes）
属性是描述数据对象特征的变量。其包含多种类型：
数值型属性（Numeric）：
这些属性包含数值数据，可以是整数或实数。
例子：日期（dates）、温度（temperature）、时间（time）、长度（length）、价值（value）、计数（count）等。
在数值型属性下又有离散型（Discrete）与连续型（Continuous）：
离散型（Discrete）：属性的值是可数的，通常是整数。例如，计数（如产品数量）。
连续型（Continuous）：属性的值可以在一定范围内取任意值。例如，温度（可以是23.5度）。
特殊情况：二元/布尔型属性（Binary/Boolean）：这些属性只有两个可能的值，通常用来表示“是”或“否”、“存在”或“不存在”等二选一的情况。

除了数值型还有分类型数据（Categorial）：
这些属性包含分类数据，通常表示没有数值意义的标签或名称。
例子：眼睛颜色（eye color）、邮政编码（zip codes）、字符串（strings）、等级（如 good, fair, bad）、身高分类（如 tall, medium, short）。
在分类型数据下分为名义型（Nominal）与有序型（Ordinal）：
名义型（Nominal）：属性的值没有顺序，不能进行比较。例如，眼睛颜色（蓝色、绿色、棕色）。
有序型（Ordinal）：属性的值有顺序，但值之间的差异不一定相等。例如，电影评级（G、PG、PG-13、R）。

### 1.2.2 数值型数据（Numeric Data）
将数值数据视为点或向量非常方便。
对于小维度的数据，我们可以绘制数据。可视化有助于理解数据的分布、识别模式和异常值。

我们可以使用线性代数来处理数据矩阵。这在数据降维、主成分分析（PCA）、线性回归等应用中非常有用。

### 1.2.3 向量数据库（Vector Databases）
向量数据库是处理数值数据的一种特殊方式，在这种特殊情况下，每个数据对象都被表示为一个多维数值向量。
传统的数值数据通常直接存储对象的属性值，如温度、湿度等。
而在向量数据库中，存储的是对象的嵌入表示（embedding），这是通过某些机器学习算法生成的。
嵌入向量是完全稠密的，并且没有明确的解释，因为它们是通过机器学习模型学习得到的，而不是直接对应于可解释的属性。
尽管嵌入向量没有明确的解释，但它们在表示对象之间的语义关系方面非常有效。

#### 1.2.5.1 分箱（Binning）
分箱是一种数据处理技术，它将数值型数据的连续范围分割成一系列离散的区间或“箱子”。
每个箱子（或区间）对应一个分类标签，例如下图中的“Low”（低）、“Medium”（中）、“High”（高）。
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/ffefe15b967241ac9778184794ae47bf.png)
或者刚刚的年龄箱子“20s”、“40s”、“50s”。

那我们如何决定箱子的数量呢？
1. 箱子的数量可以根据分析的需要来确定。更多的箱子可以提供更细粒度的数据，但可能会增加分析的复杂性。
2. 在确定箱子的数量时，可能会利用对数据领域或业务背景的理解。例如，在处理收入数据时，可能会根据常见的收入水平来设置箱子的边界。

那我们如何决定箱子的大小呢？
子的大小取决于数据本身和具体的应用需求。
有多种箱子大小的选择：
1. 等宽箱子（Equi-width bins）：
所有箱子具有相同的宽度。例如，将时间分割为十年一个区间，每个十年就是一个等宽的箱子。
问题是这样的话，某些箱子可能非常稀疏或为空，特别是当数据分布不均匀时。
2. 等深箱子（Equi-size (depth) bins）：
选择箱子使得它们都包含相同数量的元素。这种方法将数据分割成不同的分位数（quantiles），如前10%、接下来的10%等。
等深箱子会导致某些箱子可能非常小，这可能导致分析时的不稳定性或不准确性。
3. 等对数箱子（Equi-log bins）：
使用对数尺度，使得相邻箱子的大小比值是常数。例如，如果 log(upper bound)−log(lower bound) 是常数，则箱子是等对数的。
这种方法适用于偏态分布（skewed distributions），即数据分布不是对称的。
4. 优化箱子（Optimized bins）：
使用一维聚类算法来创建箱子。这种方法可以根据数据的实际分布来动态地确定箱子的大小和位置，以更好地反映数据的特性。

下图给出了例子。
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/d0e663081a4741cf98a12705d264a6a7.png)
蓝色（Blue）：等宽箱子（Equi-width）
这些箱子覆盖了数值范围 [20, 40, 60, 80]，每个箱子的宽度相同。等宽箱子意味着每个箱子包含的数值范围是一致的。
红色（Red）：等深箱子（Equi-depth）
这些箱子是按照每个箱子包含相同数量的数据点来划分的。在这个例子中，每个箱子包含2个数据点。等深箱子确保了每个箱子有相同的数据点数，但箱子的宽度可能不同。
绿色（Green）：等对数箱子（Equi-log）
这些箱子是基于对数尺度划分的，公式$\frac{\log(end)}{\log(start)} = 2$表示每个箱子的结束值是对数尺度上开始值的两倍。等对数箱子适用于处理偏态分布（skewed distributions），其中数据值在数值范围的低端比高端更密集。

### 1.2.6 物理数据存储方式及其特点
如果有严格的模式（schema），并且数据相对稠密（即缺失值或空值较少）。数据可以存储在关系型数据库（Relational Database）中。
分隔文件（Tab or Comma separated files）包括TSV（Tab-Separated Values）或CSV（Comma-Separated Values）文件，Excel表格，关系型表格同员工适合有严格的模式，并且数据相对稠密（即缺失值较少）。

平面文件（Flat file）包含三元组（triplets）：记录ID、属性、属性值。这是一种非常灵活的数据格式，允许同一属性有多个值（例如电话号码）。

JSON 和 XML 格式是数据描述的标准，比关系型表格更灵活，用于存储和传输数据的标记语言，它们可以表示复杂的数据结构。然后使用解析器（Parsers）被程序读取和处理。

CouchDB：另一个NoSQL数据库，也支持存储和查询JSON格式的数据。
MySQL：虽然MySQL是一个关系型数据库管理系统（RDBMS），但它也支持通过MySQL Connector/C和MySQL Shell等工具来存储和查询JSON数据。

### 1.2.9 依赖数据（Dependent Data）
在传统的表格数据中，通常假设每条记录或对象是相互独立的。然而，在某些情况下，数据点之间可能存在明确的依赖关系，这些关系对于数据分析和建模至关重要。
包含以下四种：
1. 有序/时间序列数据（Ordered/Temporal data）：
这种类型的数据具有时间顺序，我们知道数据的时间顺序。例如，股票价格、天气记录或日志文件。
2. 空间数据（Spatial data）：
这类数据涉及特定位置上的数据，如地理信息系统（GIS）中的位置数据。
3. 时空数据（Spatiotemporal data）：
结合了空间和时间维度的数据，例如，某个地点在不同时间点的环境监测数据。
4. 网络/图数据（Networked/Graph data）：
这种类型的数据包含实体之间的成对关系，如社交网络、交通网络或生物网络。
